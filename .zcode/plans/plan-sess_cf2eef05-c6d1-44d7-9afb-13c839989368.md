# 方案:api-savior-docs 引入可插拔的"代码发现引擎"层

## 一、要解决的三个实际问题
1. 单接口文档生成依赖 agent 记得先跑 codegraph 定位 Controller——这是 prompt 约定,不可靠,忘了就全量扫描;
2. 解析报出未解析 DTO 类型时,要用户手动猜它在哪个模块、补 --source/--classpath、重跑;
3. DTO 改动后不知道哪些接口文档过期了,只能全量重新生成。

## 二、设计原则(两条铁律)
1. **引擎只做位置查询,不做语义**。已用 codegraph 1.0.1 的索引 schema 核实:它有 field/enum 节点和 calls/extends 关系边,但注解参数(@JsonProperty 的值、required 标志)、字段类型、泛型实参替换、二进制 JAR 都不在索引里。所以发现引擎只回答"文件在哪、符号定义在哪、改动影响哪些文件";字段、wire 名、枚举等语义抽取 100% 仍由现有 javac 扫描器和 FastAPI adapter 完成,文档正确性的来源不变。
2. **无引擎时行为与现在完全一致**。没有 codegraph 或索引不可用时,自动回到今天的路径,零新依赖;有引擎时,对同样的输入文件集,输出也必须与现在逐字节一致。

## 三、架构:发现层抽象协议
新增一个独立的"发现层"模块,定义一个只有 4 个操作的引擎协议:
- **sync()**:同步索引,保证不读旧数据;
- **source_files()**:列出索引内的源文件清单;
- **locate()**:按符号名(类/方法)定位定义位置;
- **affected()**:给定改动文件,返回受影响的符号。

三个后端实现:
- **CodeGraphEngine**:封装 codegraph CLI,所有 CLI 细节(JSON 格式、命令名、退出码)封死在类内部,协议里不出现任何 codegraph 概念;
- **NullEngine**:即现状行为(文件系统遍历,locate 恒为空)——降级不再是散落各处的特判,而是"能力缺失就自然跳过对应场景";
- **FakeEngine**:测试专用,CI 不需要安装 codegraph。

留在发现层之外(宿主侧)的语义逻辑:注解匹配、由符号位置反推 source root、歧义上报格式、自动重跑的轮数上限——这些是 skill 的领域知识,与引擎无关。

## 四、四个工作场景
**场景 0|引擎探测**(每次运行第一步):源码根存在 `.codegraph/` 且 CLI 可用 → sync 后走引擎路径;否则走现状路径。提供 `--no-codegraph` 显式关闭。

**场景 A|全量生成**:引擎给文件清单(免递归遍历)→ 清单上做 @RestController/@FeignClient 文本匹配 → 命中文件作为扫描入口,javac 按需解析依赖的 DTO。清单可疑(文件不存在/命中为空但源码非空)→ 回退现状路径。

**场景 B|单接口生成**:用户只给接口方法名,不再需要先传 Controller 路径。引擎按方法名定位 → 确认所在类带映射注解 → 进入现有单接口快路径。同名方法多个命中 → 沿用现有歧义机制列出候选。

**场景 C|未解析类型自愈**(体验改善最大):生成后若报未解析 DTO 类型 → 每个类型名查引擎 → 找到定义文件 → 反推 source root 自动补齐 → 重跑(上限 2 轮,每轮自动补了什么打日志,可复核)。索引里查不到(比如只在二进制 JAR 里)→ 保持今天的警告,不猜、不编造。

**场景 D|增量再生成**(全新能力):给改动文件列表 → affected 找出受影响的接口 → 逐个走场景 B,只重新生成对应的文档段落。新增 CLI 入口,不影响现有用法。

FastAPI 侧复用同一协议:按路由函数名定位文件、未解析 import 自动补源码根;Depends 链绑定等语义规则不动。

## 五、失效处理(全部内建)
- 索引过期:每次先 sync;sync 失败 → 降级并提示;
- 引擎返回的文件一律做存在性校验,不过 → 回退;
- 任何引擎异常不得让文档生成失败,最坏情况等于今天的行为。

## 六、实施阶段(每阶段独立可验收)
- **阶段一**:发现层协议 + 三个后端 + 场景 B、C。价值最大、改动最小。
- **阶段二**:场景 A(全量生成收窄)。
- **阶段三**:场景 D(增量再生成)收尾。
- 每阶段验收标准:① 无 `.codegraph/` 时输出与当前版本逐字节一致(现有测试套全过);② FakeEngine 单测覆盖定位/自愈/歧义三条路径;③ 一个真实 Spring 多模块仓库手测:去掉手动 --source,验证未解析类型被自动补齐。
- 文档同步:SKILL.md 删掉"agent 先跑 codegraph explore"那条 prompt 约定(改为程序内置),README 增补发现引擎章节。

## 七、主要风险与对策
- 索引陈旧导致定位错 → sync + 存在性校验 + 可疑即回退;
- 全量收窄漏掉 Controller → 清单完整性校验,存疑即全量;
- 自愈循环失控 → 轮数上限 + 补充 root 去重;
- 输出漂移 → "引擎路径与现状路径输出一致"作为显式测试断言。
